# Rhizome

**Stop managing software. Start growing it.**

Software identified by what it *is* rather than by a name someone chose: every definition carries a
fingerprint computed from its structure and from everything beneath it. From that one change follow
no files, no packages, no version numbers and no dependency conflicts - only a graph of definitions,
looked at through views; taking a behaviour without the box it shipped in; changing a thing without
disturbing anyone who uses the original; a program that sees only what built it; and one kind of
person, at some distance from any given piece, where today there are developers and users.

Read it back and there is one move, repeated: **replace a guess with a calculation.**

- [**MANIFESTO.md**](MANIFESTO.md) - the whole idea, for a reader who is clever and curious and need
  not write software. Start with Part Four to see it in motion.
- [**ROADMAP.md**](ROADMAP.md) - Hypha, the first milestone: the content-addressed core, in eight
  phases, with graft - structure turned back into running code - as its capstone.
- [`data/`](data) - its concepts, the decisions taken (each with what was rejected), its backlog and
  its path, kept the [ocoeco](https://github.com/open-commons-observatory/ocoeco) way and shown in
  the [Open Commons Observatory](https://open-commons-observatory.github.io/).

**Status: the idea is whole and planned; nothing is built yet.** It is kept on the periphery on
purpose - recorded completely, so it is ready when the old ways of files and packages get in the way
enough. [Rhizoid](https://github.com/git-rhizoid) lives beside it: owned git cuttings, for the world
of files as it is today.
